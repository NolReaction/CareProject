# Район для тестов

Площадка 36 × 32 м. Центральный перекрёсток соединён с объездным маршрутом:
можно обходить здания с нескольких сторон и проверять стрельбу на разных дистанциях.
На северо-западе расположен склад с погрузочной площадкой, на юго-западе мастерская,
на северо-востоке подстанция. Юго-восточная площадка — тир с пятью неподвижными капсулами.

В Hierarchy раскрой `MVP_TestEnvironment`. Каждый объект/участок имеет именованный
корень и `IntercomWorldAnchor`: идентификатор, роль и размер занятого места.
Выделенный объект показывает свой контур и роль в Scene.

Для замены здания раскрой его корень и меняй дочерние `Visual`/видимые MeshRenderer-объекты.
Объекты `Collision - ...` держат отдельные физические границы. Их можно подогнать
под новую модель отдельно. Сохраняй корень, его World Anchor и IntercomOccluder.
У мишени коллайдер и IntercomTargetDummy стоят на корне, графика находится в `Visual - replace capsule`.
Ссылки Visual и Body Renderer нужно обновить, если заменяется вся графика мишени.

Пустые точки Player start, Future wave, Future pickup и Future exit резервируют места
для будущего игрового цикла. Они пока ничего не спавнят и не запускают.

`DistrictLayout.json` — исходные координаты блоков, зон и мишеней.
`IntercomDistrictSetup` создаёт этот план в редакторе только при отсутствии
`IntercomDistrictMarker`. Повторный Setup сохраняет ручные изменения.
Чтобы изменить уже построенную сцену, двигай объекты в Unity и сохраняй сцену.

Для разработчика: `Tools/BuildDistrictScene.py` пересобирает все дочерние объекты
MVP_TestEnvironment из JSON, включая пользовательские правки внутри этого корня.
Запускай его только при намеренной полной пересборке блокоута с сохранённой копией сцены.
Обычный игровой/редакторский Setup этот Python-скрипт не запускает.

План сверху: `Docs/DistrictPlan.png`. Проверка проходов: `Validation/DistrictLayout.json`.

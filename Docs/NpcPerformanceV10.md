# NPC: появление, смерть и паузы кадра — V10

## Что изменилось

Раньше пул врагов был ограничен восемью местами, но заполнялся лениво: первое появление в каждом месте создавало целого робота прямо во время игры. Это пять примитивов Unity, временные коллайдеры, компоненты, сетка сектора удара, массивы и начальная настройка. Такой пакет работы мог давать рывок на первых появлениях.

Теперь Mission Director готовит не более одного врага за кадр, пока открыто меню режимов. Все восемь подготовленных врагов выключены: они не видны, не двигаются, не атакуют и не входят в счётчик задания. Если выбрать режим сразу, остаток подготовки проходит во время начальной задержки перед первым врагом; герой уже может двигаться. Само появление берёт готовый объект. Последующие жизни, смерти, волны и повтор задания переиспользуют тот же пул.

Дополнительно:

- Смертельное попадание не вызывает ненужный поиск видимости для уже мёртвого бота.
- Неподвижный цвет материала не отправляется заново каждый кадр. После окончания падения трупа его поза больше не переписывается до возврата в пул.
- Строки цели и указателя спасения обновляются при изменении значения, а не при каждом проходе интерфейса.
- Навигация учитывает не только число запросов, но и выполненную работу поиска. После достижения мягкого лимита в 1200 раскрытых клеток следующие поиски ждут следующий кадр. Начатый поиск завершается корректно; лимит может быть превышен одним поиском. Старый безопасный маршрут сохраняется при отсрочке.

## Где настройки

`IntercomMissionDirector.PreparedEnemyCount` — число подготовленных объектов, от 0 до 8. Игровой предел одновременно живых врагов по-прежнему задаётся в профиле задания (`maximumAlive`).

В `IntercomNpcNavigation`:

- `maximumSearchesPerFrame` — верхний предел количества поисков за кадр;
- `maximumExpandedNodesPerFrame` — мягкий предел суммарной работы поиска;
- `ExpandedNodesThisFrame` — выполненная работа текущего кадра для диагностики.

## Что проверено и что ещё требует Unity

Автономные проверки исполняют производственные компоненты с узкими заменами Unity API. Они проверяют подготовку по одному объекту, отсутствие видимых врагов в меню, запуск по быстрому клику, прохождение 50 убийств и пяти волн, повтор задания, спасение, блокировки управления и ограничение поиска. Отдельно производственная фабрика/контроллер проходит 100 повторных жизней без новых GameObject, материалов и запросов Destroy после подготовки.

Это не измерение FPS в Unity. GPU/шейдеры не прогреваются без фактического кадра отрисовки, поэтому такую гарантию этот патч не даёт. Для проверки на устройстве: Development Build → Profiler → CPU Timeline, GC Alloc и Rendering. Сравнить первый запуск, первые восемь появлений, обычное убийство и последнее убийство волны; отдельно проверить Mono/IL2CPP и Audio. Deep Profile для обычного замера отключить: он сам добавляет заметные накладные расходы.

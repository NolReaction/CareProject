# Проверка игры в Unity

В среде подготовки V20 не установлены Unity Editor и действующая лицензия.
Поэтому нативный Play Mode, PhysX, Animator и Profiler здесь **не запускались**.
Отчёт `Validation/Reports/NativeUnityAvailability.json` имеет статус `NOT_RUN`.
Автономные C#-проверки и измерения Blender не заменяют этот запуск.

## Одна команда в редакторе

1. Открой полный проект в Unity **6000.3.26f1**, дождись импорта и компиляции.
2. Сохрани открытые сцены и останови Play Mode.
3. Выбери **Tools → CareProject → Development → Verification → Run 150s Native Check**.
4. Оставь окно Unity активным и не управляй героем во время прогона. Команда сама
   откроет учебную сцену и запустит Play.

Проверка использует настоящие игровые компоненты: предварительно созданный пул,
выход роботов из земли и люков, риг и Animator, пистолеты со swept-столкновением,
получение урона, разлёт деталей, повторные появления и перезапуски. Герой на время
проверки управляется автоматически. Переход героя между точками тестового маршрута
выполняется непосредственно командой проверки; это не тест обычного ввода движения.

Есть проверка паузы, выхода за радиус замаха, двух побед, смерти героя и повтора,
свободного режима и настоящего маршрута спасаемого союзника. Для ускоренного прогона
создаются временные копии карточек миссий. Сами `.asset`, сцена и сохранение игрока
не перезаписываются. Награды и покупки работают во временном профиле; он удаляется
после теста. После остановки возвращается прежний набор сохранённых сцен.
Массовый разлёт проверяется отдельно: сначала фиксируются минимум два взрыва и
активные детали, затем проверяется их собственное исчезновение без команды очистки.

Проверка ограничена 150 секундами. **PASS** появляется только после выполнения
сценариев в настоящем Play Mode. Ошибка, ручная остановка, перекомпиляция или
незавершённый сценарий дают `FAIL`/`CANCELLED`, а не успешный результат.
Остановить вручную: **Verification → Stop Native Check**.

## Что прислать после запуска

**Verification → Open Last Native Report** открывает расположение
`CareProject_Native_Latest.json`. Рядом находится папка конкретного прогона:

- `Summary.json` — этапы, ошибки, число повторных использований, появления,
  подтверждённые попадания и результат проверки;
- `Frames.csv` — последняя ограниченная история настоящих кадров: время,
  `Main Thread` в наносекундах, `GC Allocated In Frame`, сборки мусора,
  число врагов/появлений/убийств, работа навигации и эффекты.

Недоступный счётчик записывается как `-1`; он не считается нулевой затратой.
Сводка содержит среднее время кадра за прогон, p95/p99 ограниченной истории,
максимум и число кадров дольше 33/50 мс. Замеры редактора включают его расходы.
Для оценки телефона нужен отдельный Development Build и подключённый Profiler.

Для обычного ручного воспроизведения задержки остаётся прежняя команда
**Development → Performance → Open Last Capture**. Автоматический прогон сохраняет
свой CSV отдельно и не заменяет обычную запись кадров.

## Запуск из командной строки

На машине с установленным и лицензированным Unity:

```text
Unity -batchmode -projectPath "ПУТЬ_К_ПРОЕКТУ" -executeMethod IntercomMvp.Editor.IntercomNativeVerification.RunFromCommandLine -logFile "native-check.log"
```

Не добавляй `-quit`: команда сама завершает редактор после выхода из Play Mode.
Код выхода `0` соответствует PASS, `1` — ошибке/отмене. Без графического устройства
такой запуск не подтверждает качество рендера, шейдеров или производительность GPU.
Сам пакетный запуск здесь не проверен. Если среда не сообщает активный фокус
приложения, игровые компоненты сохранят свою защиту паузы/фокуса, а сценарий
завершится ошибкой. Подменять системные события для получения PASS команда не будет.

Официальные API: [Play Mode state changes](https://docs.unity3d.com/ScriptReference/EditorApplication-playModeStateChanged.html),
[ProfilerRecorder](https://docs.unity3d.com/ScriptReference/Unity.Profiling.ProfilerRecorder.html),
[LastValue и завершённый кадр](https://docs.unity3d.com/ScriptReference/Unity.Profiling.ProfilerRecorder.LastValue.html).

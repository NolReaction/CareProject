# Устройство CareProject V9

## Основная идея

Настройки хранятся в ресурсах проекта; игровые компоненты читают их и выполняют
свою работу. Модель отвечает за внешний вид, а Collider — за столкновения.
События соединяют выстрел, звук и эффекты, чтобы добавление нового оружия не требовало
переписывать движение робота или материалы мира.

## Основные системы

| Система | Главные файлы | Ответственность |
| --- | --- | --- |
| Ввод | IntercomPlayerInput, IntercomTwinStickState | Клавиатура, мышь, экранные стики |
| Интерфейс | IntercomWorkshopHud, IntercomHudLayout | Выбор режима, цель, результат, реальные HP/патроны, стики и безопасные зоны экрана |
| Движение | IntercomPlayerMotor | Перемещение капсулы, направление, скорость |
| Опора и поворот | IntercomGroundFeedback | Положение корпуса, ботинки и переступание |
| Магазин | IntercomWeaponMagazine, IntercomMagazineState | Патроны в магазине, перезарядка и бесконечный резерв |
| Жесты рук | IntercomCharacterAnimation | Перезарядка, ожидание и реакция на стену поверх клипов |
| Поза оружия | IntercomWeaponPose, IntercomWeaponPoseClock | Поднять руки, держать, стрелять, опустить |
| Настройки оружия | IntercomWeaponDefinition | Урон, интервал, пули, звук, вспышка, гильза, ссылка на позы |
| Пули | IntercomSimpleShooter | Выпуск, движение, проверка пройденного отрезка, попадание |
| Получение урона | IIntercomDamageable, IntercomHealth, IntercomTeam | Здоровье, команды, запрет собственного/дружественного урона и защита после попадания |
| Жизнь героя | IntercomPlayerVitality | Общая блокировка при смерти/меню и явный повтор |
| Поведение NPC | IntercomNpcDefinition, IntercomNpcBrain, IntercomNpcController | Параметры, состояния, движение, проверка удара и реакция капсулы |
| Навигация NPC | IntercomNpcNavigation, IntercomNavGrid | Общая сетка препятствий, ограниченное число поисков пути и открывшиеся проходы |
| Режимы и волны | IntercomMissionDefinition, IntercomMissionState, IntercomMissionDirector | Условия миссии, счётчик побед, ограниченный набор переиспользуемых врагов и завершение |
| Спасение | IntercomRescueAlly | Подход для присоединения, здоровье союзника и движение к герою по маршруту |
| Старый тест NPC | IntercomNpcArena | Сохранён для отдельной проверки; в миссионной сцене отключён |
| Тренировка | IntercomTargetDummy | Здоровье, реакция на удар и восстановление мишени |
| Предметы двора | IntercomReactiveProp, IntercomPropState | Состояния выбранных объектов, визуальные реакции и освобождение прохода |
| Эффекты | IntercomCombatEffects | Переиспользуемые вспышки, гильзы и частицы попаданий |
| Аудио | IntercomPlayerAudio, IntercomAudioProfile | Музыка, шаги, выстрелы и удары |
| Камера | IntercomCameraFollow, IntercomCameraTracking | Композиция, свободная зона и плавное сопровождение |
| Перекрытия | IntercomCameraOcclusion, IntercomOcclusionGeometry, IntercomOcclusionState | Проверка мешей перед корпусом героя и плавная прозрачность |

Runtime содержит общие системы. Editor — инструменты, которые работают только
в редакторе Unity. Game — настройки конкретного содержимого игры. Art и Audio —
общие ресурсы. Source — редактируемые исходники. Tools и BlenderTools — ручные
генераторы; обычный запуск игры не перестраивает модель или карту.

## Что происходит при выстреле

Ввод сообщает о желании стрелять. WeaponPose учитывает поднятие рук и темп оружия,
запускает отдачу и уведомляет Shooter. Shooter после анимации берёт актуальное положение
ствола, проверяет преграду перед ним и активирует пулю из ограниченного набора.
Фактически выпущенный залп тратит патроны и запускает отдачу/звук, а каждый ствол —
вспышку и гильзу. Если ствол оказался внутри стены, пуля из него не создаётся
и патрон не списывается. При пустом магазине огонь блокируется на время перезарядки.

Пуля проверяет весь пройденный за кадр отрезок, чтобы не перепрыгивать тонкие стены.
При встрече с целью передаёт урон объекту, который реализует IIntercomDamageable.
Событие попадания содержит позицию, нормаль и тип поверхности для звука/частиц.
Системы не создают новую физическую Rigidbody для каждой пули и каждой гильзы.

Параметры пули берутся из оружия при запуске. Уже летящая пуля должна сохранять
свой урон и движение при последующей смене настроек. Произвольная замена визуальной
модели оружия и анимаций пока остаётся задачей будущей системы экипировки.

## Как работает прозрачность V5

Из камеры проверяется девять точек на области корпуса робота. Отрезки заканчиваются
перед ним: здание позади персонажа не может перекрыть эти лучи. Большой габарит
предмета служит только быстрой предварительной проверкой; решение принимает
пересечение с настоящими треугольниками меша. Соседние предметы проверяются отдельно.

Геометрия для проверки подготавливается один раз на каждый уникальный меш и
используется всеми его экземплярами. После выхода из-за укрытия видимость плавно
восстанавливается; короткие касания края не должны мигать. Параметры находятся
на Main Camera → Intercom Camera Occlusion. Для импортированного статичного
укрытия нужен MeshRenderer и включённый **Read/Write** в настройках импорта модели.
Без читаемого меша предмет остаётся непрозрачным. Read/Write сохраняет геометрию
в памяти CPU, поэтому его следует включать у нужных укрытий, а не у всех моделей игры.

Если один дом собран из нескольких отдельных частей, можно добавить на его корень
Intercom Occluder и включить Fade Whole Hierarchy. Для целого квартала или общей
папки предметов эту настройку оставляй выключенной.

## Как добавлять содержимое

**Новый предмет окружения:** импортировать модель, назначить материалы, добавить
простые Collider и IntercomFootstepSurface. Если предмет должен получать урон,
добавить IntercomHealth или собственный компонент с IIntercomDamageable.

**Новый противник:** для изменения чисел сначала дублировать IntercomNpcDefinition.
Один контроллер может читать разные карточки. Новая модель заменит временную капсулу;
поведение и здоровье остаются отдельными системами. IntercomHealth сам по себе
не создаёт ИИ, смерть или выпадение награды; реакция подключается отдельно.
Тренировочная мишень имеет собственный сброс и не требует второго компонента здоровья.

**Новое оружие:** отдельная IntercomWeaponDefinition, модель, ствол и совместимые
позы рук. Общая система пуль и попаданий сохраняется. При росте проекта следующий
отдельный модуль — экипировка/инвентарь. Магазин и перезарядка уже вынесены в общие компоненты.

## Правила дальнейших правок

- Сохранять `.meta` при переносе ресурсов: GUID держит ссылки сцены и материалов.
- Делать изменения вне Play и сохранять сцену.
- Настраивать конкретное оружие через его карточку, не дублировать параметры вручную
  по нескольким компонентам.
- Проверять мобильную производительность на устройстве. Полигоны, материалы,
  тени, прозрачные эффекты и игровая логика требуют отдельных измерений.
- После изменения рига или геометрии ног заново проверить опору. Кости с подшипниками
  нельзя растягивать ради искусственного прижатия стопы к полу.

## Границы текущей базы

Учебный двор, один робот, пистолеты, мишени, ввод, звук и камера соединены в готовой
сцене. Есть два режима с победой/поражением, волны капсул ближнего боя, здоровье героя
и сопровождение союзника. Пока нет наград за миссии, магазина оружия, сохранения прогресса, конечного
резерва боеприпасов, сетевой игры или законченного производственного арт-пайплайна.
Новые системы следует добавлять по проверяемым шагам, сохраняя эту сцену как площадку
для быстрой проверки движения, оружия и поверхностей.

## Безопасные ссылки сцены

Unity связывает локальные объекты и компоненты числовыми fileID. В V6 исправлены
94 идентификатора поверхностей, вышедшие за диапазон signed Int64. При ручной генерации
нельзя брать максимальный ID сцены и просто прибавлять единицу: SceneRoots использует
зарезервированное крайнее значение. Генератор теперь применяет проверяемый распределитель.
Перед передачей проекта запускается `python Validation/check_scene_integrity.py`.

# Как капсула обходит предметы

Для ровного учебного двора используется общая сетка с шагом 0,4 м. Она строится
по реальным коллайдерам внутри `MVP_TestEnvironment` при запуске. Вокруг препятствий
добавляется запас 0,4 м: радиус NPC 0,32 м плюс небольшой зазор. Один экземпляр
`IntercomNpcNavigation` обслуживает всех капсульных противников.

Капсула ищет путь вокруг занятых ячеек, а затем идёт по его углам. Срезать угол
между двумя препятствиями нельзя. Движение дополнительно проверяется обычным
`CharacterController`, поэтому физическое столкновение остаётся последней проверкой.

## Что считается препятствием

- Включённые твёрдые коллайдеры окружения на высоте тела NPC.
- Здания, ограды, бетонные блоки, мишени и целые интерактивные предметы.
- Пол и низкие площадки до 0,18 м считаются проходимыми.
- Триггеры, контроллеры персонажей и детали выше роста NPC не занимают сетку.

Вращённые предметы проверяются по охватывающему прямоугольнику. Это намеренно
оставляет небольшой запас около углов. Между соседними NPC применяется отдельное
разведение и физическое столкновение; они не перестраивают общую сетку как здания.

Состояние известных коллайдеров проверяется раз в 0,2 секунды. Когда ящик разбит
или ограничитель сложен, отключённый коллайдер перестаёт закрывать путь. Когда
предмет восстановлен, путь снова закрывается. Сама сетка пересчитывается только
при изменениях коллайдеров; её номер версии меняется только при изменении занятых
ячеек. Поиск пути ограничен двумя запросами за кадр для всей группы.

## Где настраивать

На объекте навигации в сцене находится `IntercomNpcNavigation`:

| Поле | Значение V8 | Что меняет |
| --- | ---: | --- |
| Obstacle Root | MVP_TestEnvironment | Какая группа содержит препятствия |
| World Min / World Size | −18, −16 / 36, 32 | Границы двора в плоскости XZ |
| Cell Size | 0,4 | Размер клетки; меньше — подробнее, но дороже поиск |
| Agent Clearance Radius | 0,4 | Размер прохода с запасом под капсулу |
| Floor Height | 0 | Высота основного пола |
| Step Height | 0,18 | Проходимая высота бордюра/площадки |
| Agent Height | 1,35 | Высота капсулы для проверки навесов |
| Obstacle Refresh Seconds | 0,2 | Частота проверки изменившихся препятствий |
| Maximum Searches Per Frame | 2 | Общий бюджет поиска пути |
| Maximum Goal Snap | 1 | Допустимый поиск свободной клетки около цели |

Если добавляешь более широкого NPC, запас навигации должен быть не меньше его
радиуса. При изменении размеров сетки в Play или добавлении совершенно нового
коллайдера во время игры используй `Rebuild NPC Navigation` в меню компонента.
Отключение/включение уже существующего ящика обнаруживается автоматически.

## Если путь недоступен

Недоступная цель возвращает результат `Unreachable`. Персонаж не переносится через
стену. Точка появления один раз выбирается на свободной клетке перед созданием
капсулы. При последующем движении проверяется каждый желаемый шаг, включая
разведение соседей: так NPC не попадает в занятую клетку и не теряет путь.

Цель может стоять ближе к стене, чем позволяет запас NPC. Тогда путь заканчивается
на ближайшей свободной клетке в пределах одного метра. Дальность и видимость удара
проверяются отдельно по настоящей позиции героя. Если такой подход с нужной стороны
невозможен, поиск возвращает недоступность, а не маршрут сквозь стену.

Результат `Deferred` означает, что два других NPC уже использовали бюджет текущего
кадра. Старый путь сохраняется; запрос повторяется в следующем кадре. Пауза тоже
не запускает поиск. Очереди пропущенных шагов или ускоренного «догоняния» после
долгого кадра в навигаторе нет.

## Проверки и ограничения

`NpcNavigationTests` проверяет производственный алгоритм и компонент навигации:
1200 сравнений достижимости с независимым поиском в ширину, углы, непроходимые
стены, ограничение бюджета, паузу, изменение коллайдеров и реальные коллизии
планировки V7. Проверены маршруты между восемью точками двора. Повторные запросы
после инициализации не создают управляемой памяти в тестовой среде.

Это навигация для текущего ровного двора. Несколько этажей, мосты над проходами,
лестницы и прыжки потребуют другой модели поверхности. Проверки использовали
замены Unity API и не подтверждают фактическую работу PhysX или FPS на телефоне.

Код: `Runtime/IntercomNavGrid.cs` — сетка и A*;
`Runtime/IntercomNpcNavigation.cs` — коллайдеры и общий бюджет запросов.

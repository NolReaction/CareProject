# Навигатор проекта

Открой **Tools → CareProject → Start Here**. Окно ведёт к учебной сцене,
карточке пистолетов, позам, модели и Animator героя, настройкам ударника,
миссиям, звуку, планировке двора, свету и документации.

Вверху показано «Скомпилированная версия: V19». Надпись берётся из кода,
поэтому помогает отличить запущенный старый проект от новой поставки.
Рядом находится кнопка «Проверить / восстановить проект».

## Проверка и восстановление

**Tools → CareProject → Проверить и восстановить проект** открывает окно
«CareProject — проверка» с заголовком «CareProject · V19».

| Действие | Результат |
| --- | --- |
| Проверить файлы и версию | Отчёт о текущем коде, ресурсах, дубликатах и вложенных папках обновлений |
| Обновить импорт интерфейса и ударника | Повторный импорт нужных ресурсов после установки файлов |
| Открыть готовую игровую сцену | Открытие канонической учебной сцены из проекта |
| Восстановить отсутствующие связи (с резервной копией) | Заполнение пустых связей и повторная проверка ресурсов ударника |

Перед восстановлением сохрани все открытые сцены, выйди из Play и дождись
импорта/компиляции. Команда создаёт резервную копию сцены перед первой правкой
в `ProjectBackups`; существующие ссылки, трансформации и настройки сохраняются.
Если готовая сцена, комнаты или опорные точки отсутствуют, используй полный ZIP.
Восстановление не заменяет их старой картой из примитивов.

Кнопки выбирают ресурс в Project/Inspector. Поиск идёт по GUID, поэтому
перенос внутри Unity с сохранением `.meta` сохраняет переход к ресурсу.
Кнопка открытия сцены использует стандартный запрос сохранения текущих правок.
Само открытие навигатора не пересобирает сцену и не генерирует модели.

«Проверить ссылки разделов» проверяет основные точки входа. Это проверка
наличия ресурсов, а не запуск игровых сценариев. Папка автономных проверок
открывает `Validation` вне Assets.

`IntercomProjectPaths` содержит названия, GUID и канонические пути.
`IntercomAssetCatalog` отвечает за кешированный поиск ресурсов.
`ProjectAssetsV13.json` хранит сопоставление известных идентификаторов и путей;
его имя сохранено как служебная часть текущей структуры.
Изменение проекта через `EditorApplication.projectChanged` сбрасывает кеш.

Полный проект в новой папке открывается непосредственно из Unity Hub.
Обновление старого проекта устанавливается через `RepairProject.cmd` с закрытым
Unity: пакет V19 содержит `Payload`, а установщик проверяет файлы, сохраняет
резервные копии и убирает известные устаревшие определения до компиляции.
Не копируй только `Payload` вручную.
Текущие правила работы: [DeveloperGuide.md](DeveloperGuide.md).

## Разделы для разработчика

В **Tools → CareProject → Mobile** находятся настройка управления, Android,
iPhone и список проверок устройства. **Development → Performance → Open Last Capture**
открывает последнюю запись задержек. **Advanced → Authoring** содержит редкие
команды подготовки героя, NPC и освещения.


В Play Mode главное меню игры — отдельная система `Runtime/Frontend`.
Навигатор Tools → CareProject → Start Here нужен разработчику в редакторе;
он не заменяет страницы Home/Play/Robot/Armory. Рабочие сцена и ресурсы
продолжают находиться по указанным GUID. Точки Ground/Hatch настраиваются
компонентом `IntercomEnemySpawnPoint` непосредственно в сцене. Две крышки люков
и наземная точка используют общие ресурсы `Content/Enemies/Spawns`; портреты
главных страниц — `Content/Frontend/Textures`.

Рисованные иллюстрации главной и спасения лежат в `Content/Frontend/Artwork`.
Они назначаются в `homeDoodle` и `rescueDoodle` у `IntercomFrontEnd` на
`MVP_NpcSandbox`. Описание подготовки — `Source/Frontend/ArtPrompts.json`
в корне проекта. Поля иллюстраций меняют оформление, а не правила миссии.

Временное 3D-убежище находится в группе `MVP_MenuHub` той же рабочей сцены.
Внутри — три комнаты, отдельные мебельные объекты, четыре точки ракурса
и `Menu Room Camera`. Его готовые модули, материалы и простой шейдер лежат
в `Content/Frontend`. Пауза и счётчики боя относятся к
`Runtime/Presentation/UI`; управление паузой и отменой касаний остаётся
в `IntercomPlayerInput`.

Новый ударник находится в `Content/Enemies/Udarnik/Model/Udarnik.fbx`, исходник
Blender — в `Source/Enemies/Udarnik/Udarnik_Rigged.blend`. После первого импорта
FBX редактор подготавливает Controller/Prefab/Material и назначает
модель в пустое поле карточки врага. Стандартный граф V18 обновляется
до десяти состояний с резервной копией в `ProjectBackups`; другая назначенная
модель и неизвестный граф сохраняются. Если автоматическая подготовка остановилась,
повтори её через окно восстановления. Авторская непустая ссылка сохраняется.

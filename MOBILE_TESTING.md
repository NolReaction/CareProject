# Intercom MVP — проверка на телефоне

Проект рассчитан на Unity **6000.3.26f1** и горизонтальный экран. На экране ровно два стика: левый двигает робота относительно камеры; правый поворачивает его и запускает стрельбу при отклонении от центра. После отпускания правого стика стрельба прекращается, боевая поза некоторое время сохраняется, затем руки опускаются.

Здесь подготовлены код и настройки. **Unity Editor, сборка APK/iOS и проверка на реальном телефоне в этой среде не запускались.** Первую сборку нужно сделать у себя по шагам ниже.

## Сначала проверь сцену

1. Открой проект через Unity Hub. Если обновляешь существующий проект, сначала сохрани его копию и следуй README: свои `.meta`, материалы и сцены сохрани.
2. Открой `Tools → Intercom MVP → Open Scene`, затем выполни **`Tools → Intercom MVP → Setup Mobile Prototype`**. Это подключает управление, стрельбу, мобильные настройки, наклонную камеру и немного временного окружения.
3. Сохрани сцену: **Ctrl+S**, на Mac **Cmd+S**. Если сцена ещё не имела пути, после сохранения повтори Setup Mobile Prototype.
4. В Game выбери горизонтальные **1280 × 720** и затем более широкий формат **20:9**. В Play проверь движение через WASD/стрелки, наведение мышью и стрельбу с удержанием ЛКМ. Каждый стик можно отдельно потянуть мышью; настоящую одновременную работу двух пальцев проверяй на устройстве.

Настройка ставит текущую сцену первой во **всём общем Scene List**, сохраняя остальные записи и их включённость. Если используешь Build Profile со своим переопределённым списком сцен, отдельно проверь, что в нём сцена MVP включена и стоит первой. Чужие сцены из списка не удаляются.

## Android: локальный APK без публикации в магазине

1. В Unity Hub у этой версии Editor открой **Add modules** и установи **Android Build Support**, включая **Android SDK & NDK Tools** и **OpenJDK**. Для первого теста оставь зависимости, которые устанавливает Hub для выбранного Editor.
2. В Unity, с открытой сценой MVP, выполни **`Tools → Intercom MVP → Configure Android Test Settings`**. Меню задаёт APK, Development Build, IL2CPP и ARM64. Пользовательские идентификатор приложения и ключ подписи сохраняются; новый проект использует обычную отладочную подпись Unity.
3. В **File → Build Profiles** выбери Android и сделай его активным через **Switch Platform**; у отдельного профиля кнопка называется **Switch Profile**. Если нужно, сначала создай Android-профиль через Add Build Profile. Дождись импорта, затем повтори Configure Android Test Settings, чтобы применить параметры после переключения.
4. Убедись в активном профиле: **Development Build включён**, **Build App Bundle выключен**, сцена MVP первая и включена. Профили могут переопределять общие настройки, поэтому эти поля нужно проверить в выбранном профиле.
5. На телефоне включи **режим разработчика → отладка по USB**, подключи его кабелем и подтверди доверие/разрешение USB-отладки. На Windows для некоторых устройств нужен USB-драйвер производителя.
6. Выбери телефон в **Run Device** и нажми **Build And Run**. Для результата создай путь, например `Builds/Android/IntercomMVP-dev.apk`, вне папки Assets. Unity соберёт, установит и запустит приложение.

Для такого USB-теста публиковать игру в Google Play не требуется. Если телефон не виден, проверь разблокированный экран, USB-разрешение, кабель с передачей данных и драйвер. Если Unity сообщает об SDK/NDK/JDK, проверь установленные модули и настройки **Preferences → External Tools → Android**. Первая IL2CPP-сборка может занять заметное время.

ARM64 подходит для современных 64-битных Android-устройств. Если твой телефон поддерживает только 32-битные приложения, понадобится отдельно включить ARMv7 в Player Settings и проверить совместимость устройства с этой версией Unity.

Основание: [зависимости Android в Unity 6.3](https://docs.unity.com/en-us/engine/6000.3/manual/platform-specific/android/getting-started/sdksetup/install-dependencies), [отладка на Android-устройстве](https://docs.unity.com/en-us/engine/6000.0/manual/platform-specific/android/developing/testing-and-debugging/debugging-on-an-android-device), [Build Profiles в Unity 6.3](https://docs.unity.com/en-us/engine/6000.3/manual/building-and-publishing/build-settings/build-profiles-reference).

## iPhone: локальный тест через Mac и Xcode

1. Для обычной локальной сборки нужны **Mac, Xcode и iOS Build Support** для этой версии Unity. Версия Xcode должна поддерживать установленную на телефоне iOS. Unity создаёт Xcode-проект, окончательную сборку и подпись выполняет Xcode на macOS.
2. Выполни **`Tools → Intercom MVP → Configure iPhone Test Settings`**. В **File → Build Profiles** выбери iOS, активируй платформу/профиль, повтори меню настройки и проверь Scene List. В iOS Player Settings оставь **Device SDK**, если собираешь для настоящего iPhone.
3. Нажми **Build** и выбери отдельную папку, например `Builds/iOS`. Открой созданный `.xcodeproj`; если плагины создали `.xcworkspace`, открывай workspace.
4. В Xcode добавь свой Apple Account. У цели **Unity-iPhone** открой **Signing & Capabilities**, включи **Automatically manage signing** и выбери свой Team. Для личного бесплатного аккаунта это **Personal Team**. Если Xcode просит уникальный Bundle Identifier, задай собственный в Unity Player Settings и пересобери проект. Скрипт не подставляет Apple Account или Team.
5. Подключи iPhone, подтверди доверие компьютеру и выполни подсказки Xcode. При запросе включи **Settings → Privacy & Security → Developer Mode**, затем выбери iPhone как устройство запуска и нажми Run.

Для теста на своём iPhone можно использовать бесплатный Apple Account с Personal Team. У такой установки профиль действует **7 дней**; после истечения приложение нужно пересобрать и переустановить. Для раздачи через TestFlight позднее понадобится членство в Apple Developer Program и App Store Connect; для описанного личного USB-теста платное членство не требуется.

Основание: [сборка iOS в Unity 6.3](https://docs.unity.com/en-us/engine/6000.3/manual/platform-specific/iphone/ios-building-and-delivering/build-process), [подпись и запуск Xcode](https://developer.apple.com/documentation/xcode/running-your-app-on-simulated-or-physical-devices), [Developer Mode](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device), [условия Personal Team](https://developer.apple.com/help/account/basics/about-your-developer-account), [совместимость Xcode](https://developer.apple.com/xcode/system-requirements).

## Что проверить на телефоне

- Двумя пальцами одновременно: бег влево при стрельбе вправо; движение вверх при стрельбе вбок. Направления управления должны совпадать с экраном.
- Отпусти только один палец: второй стик должен продолжать работать. Верни правый стик в центр: стрельба должна прекратиться.
- Перенеси палец через середину экрана: он должен оставаться за своим первоначальным стиком. Отпусти за пределами круга: ввод не должен зависнуть.
- Сверни приложение во время бега/стрельбы и вернись: самопроизвольное продолжение не допускается; отпусти пальцы и начни касание заново.
- Переверни телефон в другую горизонтальную сторону: оба стика остаются доступными, не попадают под вырез экрана. В портретный режим игра не переходит.
- Зайди за высокий дом: дом скрывается целиком и возвращается после выхода. Даже скрытая стена сохраняет коллизии.
- Удерживай прицеливание в одном направлении и двигайся назад/вбок: выбираются отдельные циклы ног.
- Подойди к временному препятствию и стреляй в него: робот и снаряды не должны проходить насквозь. Мишени и урон пока не добавлены.
- Поиграй несколько минут: оцени удобство размера стиков, видимость робота, нагрев и плавность. Целевые 60 FPS — настройка, а не обещание производительности конкретного телефона.

## Что можно подкрутить

| Объект / компонент | Поля | Что меняют |
| --- | --- | --- |
| Robot / Intercom Player Input | Stick Radius At 720p, Edge Margin At 720p | Размер и отступ двух стиков |
| Robot / Intercom Player Input | Movement Dead Zone, Aim Dead Zone | Минимальное отклонение для движения и стрельбы |
| Robot / Intercom Player Input | Controls Opacity | Прозрачность стиков |
| Robot / Intercom Mobile Runtime Settings | Target Frame Rate | Целевая частота; например 30 для проверки слабого устройства |
| Main Camera / Intercom Camera Follow | Настройки ракурса и следования | Высота обзора, наклон и плавность камеры |

Игровая картинка заполняет экран; расположение стиков учитывает `Screen.safeArea`. На устройстве разрешены обе горизонтальные ориентации. Мобильный компонент повторно применяет их после возвращения в приложение; в обычном Desktop Play Mode он не меняет ориентацию и лимит кадров. На Android используется поворот по датчику устройства.

Меню подготовки **не переключают платформу и не запускают сборку автоматически**. Для релизной публикации позже отдельно понадобятся профиль выпуска, иконки, подпись и настройки магазина — этот прототип пока предназначен для локального тестирования.

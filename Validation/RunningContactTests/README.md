# Running contact regression

Run `dotnet run --project Validation/RunningContactTests` with a .NET 8 SDK. The project copies its measured pose fixture and sole profile to the output directory; no Blender, Unity, network, or machine-specific paths are required. Optional arguments replace the fixture/profile and write a metrics report and pose traces:

```text
dotnet run --project Validation/RunningContactTests -- Fixture.json SoleProfile.json metrics.json trace.json
```

The production GroundFeedback, Motor, cadence, direction, and turning classes compile against narrow engine stand-ins. The harness supplies measured movement outputs to Motor and executes GroundFeedback Update/LateUpdate against measured source poses; it does not simulate input acceleration or controller collisions. Separate motor tests cover input/cancellation behavior. The fixture contains 129 measured poses for each of the eight Run clips and the Idle calibration pose. Bone world poses are converted to local TRS before interpolation; the four physical 45-degree diagonal cases blend local rotations with 4/7 side and 3/7 forward/backward weights, preserving rigid link lengths. The side stride is 0.75 times the forward stride, so a physical 45-degree direction maps to Animator parameters (0.8, 0.6). Each case advances the wrapper at pace multipliers 0.9, 1.8, or 2.1 times its directional stride reference (full pace: 2.1 m/s forward/backward, 1.575 m/s sideways, 1.781909 m/s diagonally) with the production cadence convention, at 60 Hz, and repeats with capsule-height errors of -27, 0, and +27 mm. Every legacy case is compared with contact correction disabled. V5 adds 216 corrected cases: the same twelve clips/directions and three height offsets at 30/60/120 Hz, with playback rates 1.25 and 2.5 and the production rigid stroke scale 1.32. These correspond to forward speeds 1.65 and 3.3 m/s (side speed is still 0.75 times forward). At 30 Hz a 0.0125-cycle starting phase ensures two fully flat samples can be measured at the fastest cadence; 60/120 Hz cases start at phase zero. This is sampled coverage, not every possible phase or frame rate.

Floor measurements use original mesh bind coordinates and Foot/Toe weights from `SoleProfile.truth.json`, independently of the runtime anatomical profile calibration. The compact selected points are verified against the full deformed mesh separately; they are not a claim that the fixture contains every vertex. This test checks ground contact and motion, not boot/body intersections. Temporal interpolation of the 129 source poses is not Unity Animator sampling. The explicit 2 mm source-minimum comparison allows the difference between interpolating a minimum and interpolating articulated bone poses; the measured final fixture error is recorded in the report.

Assertions require flat clearance of 1–6 mm, mean flat slip below 5 mm/s (single-frame slip below 20 mm/s), whole-cycle penetration no deeper than 0.5 mm, ankle speed below 6 m/s and Body speed below 4 m/s at the legacy 2.1 m/s pace (these velocity envelopes scale proportionally at the faster V5 travel speed), calf correction below 45 degrees, and Body correction below 65 mm. They also check immutable leg local positions/scales and rigid link lengths, real contact phases and counts, and no invented contact on teleport, focus/pause resume, flight, or ordinary idle. A separate `TurningRigTests` suite protects the stationary turning behavior.

The stand-ins reproduce recursive affine transforms, including parent scale, and a horizontal ground plane. They do not run Unity Animator, PhysX, GPU skinning, rendering, or audio. Full-mesh Blender checks and a Unity play check remain separate forms of verification.

To regenerate the pose data with Blender, run `blender --background --python Validation/RunningContactTests/ExportSourceFixture.py -- Source/Robot/intercom-armed.blend Validation/RunningContactTests/Fixture.json`. The exporter reads source data and verifies its SHA-256 before and after. `ValidateSoleProfile.py` similarly compares the frozen profile with every deformed boot vertex at all 129 phases: pass the blend path, `SoleProfile.json`, and a report output path after `--`. These scripts only write the explicitly requested fixture/report; they do not save or edit the blend file.
